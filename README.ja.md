# Moat

**数値を報告する前に、堀を掘る。**

## まず、実際に起きたこと

ある手法に「正解の総量」だけを渡し、**置き場所を当てるのが仕事**という条件で
測りました。スコアは 0.162。比較用の陰性対照（1つずれた相手の正解と突き合わせる）
は 0.062 なので、**明確に勝っています**。普通ならここで「置き場所を当てられて
いる」と報告します。

ところが、**出力を転置しても 0.001 しか下がらず、50ピクセルずらしても 0.0003
しか下がりませんでした。** 位置の情報を破壊する操作が、スコアを動かさない。
この手法は場所を当てていません。**重なっていたのは「量」だけ**でした。

1つずれ対照だけで判定していたら、そのまま発表していました。

## 誰のためのスキルか

機械学習や画像処理の**実験を回して、その数値を根拠に判断する人**です。
ベンチマークを作る、評価指標を決める、モデルやパイプラインを採点する、
結果を書き起こす、数値の意味を決める —— こうした仕事を
AI コーディングエージェントにやらせるときに使います。

逆に、**機能実装や UI には使いません。** 判定は一つで、
**「結果が逆に出たら、自分の言うことが変わるか」**。
変わらない仕事なら、このスキルの出番ではありません。

## なぜ必要か

研究のコストの大半は、結果を計算することではありません。結果を
**棄却可能にする**ことです。それを露呈させたはずの対照、値を先に知っていた
セル、誰かが結果を見る前に書いておいた閾値。

この作業を要求する人は、どこにもいません。答えへの最短距離を進むエージェントは
全部飛ばします。そして**飛ばしても、答えの見た目は変わりません。**
だから誰も気づかない。

これは意図的に高コストです。「動く最小のものを作る」エージェントが欲しいなら、
最小主義のスキルを使ってください（良いものがいくつもあります。本スキルは
その競合ではなく、**用途が逆**です）。こちらを使うのは、
**誤った数値のコストが、無駄になった午後より高い**場合です。

## 10の規則

`moat` は測定の仕事に常時かかる指針です。どの規則も、
**撤回する羽目になった結果の代価**として得られたものです。適用順に並べています。

1. **見る前に閾値を登録する**（事前登録 / pre-registration）。
   条件、主要評価指標、層別、合否の閾値、そして**各結果が何を意味するか**まで、
   ファイルに書いてコミットしてから走らせる
2. **パイプラインの外に、答えを知っているセルを1つ置く。**
   再現しなければ、その実験の他の数値は一切読まない。同じパイプラインの
   2箇所が一致しても、それは**パイプラインが自分自身と一致している**だけ
3. **陰性対照（negative control）は、実際に起こりうる誤りを1つずつ
   名指しで実装する。**期待されるスコアを先に書く。
   「x と y を入れ替える」は名指しではない。**どの層で起こる誤りか**を言う
4. **器具の健全性確認と陰性対照は、主要な数値より先に印字する。**
   対照に落ちた条件は**読まない**。その数値を見出しや要約表に出さない
5. **自明解は比較対象ではなく「条件」として表に並べる。**
   何もしない / 全部やる / 既存の道具だけ（モデルなし）。
   **自明解のスコアが恒等式になる場合は、どの恒等式かを書く。**
   「全画素を塗る」が正解の面積率とぴったり一致するのは測定ではなく算術で、
   他の全条件はその算術と比較されている
6. **数値は、その量・設定・閾値を連れて動く。**
   `0.26（最良）`ではなく`0.26（モデルB / 1024px / ホールドアウト、閾値0.24）`。
   **判定語も閾値を連れて動く。**「有意」「局在している」「飽和」「大きい」は、
   判定に使った数値がなければ読めない
7. **学習した数値の隣に、学習なしの度数表を1つ置く。**
   入力の安い特徴量1つ、度数表、当てはめなし。
   それで学習の利得の大半が再現できるなら、測っていたのはその特徴量
8. **母集団を混ぜない。**課題が違うプールを平均しない。ほぼ空の単位を平均に
   入れない（何も無い所で点が取れてしまう）。平均が一致していても別々に出す
9. **撤回は、最新の1か所への追記ではなく、全ての複製先への1巡。**
   1箇所でも残った取り下げ済みの数値は、後日**前提**として戻ってくる
10. **データが何を写しているかは、その領域の専門家が決める。**
    エージェントの読みは専門家に確認を求める仮説であって、
    専門家の判断を覆す根拠ではない。疑わしいときは縮小版で議論せず、
    元データを原寸で見る

## コマンド4本

| コマンド | 何をするか |
|---|---|
| `/moat-register` | 事前登録ファイルを書く。条件、主要評価指標、層別、器具確認、陰性対照、合格基準、そして**この実験では決められないこと**。落ちようのない基準は却下する |
| `/moat-controls` | 陰性対照を誤りの型ごとに提案し、「対照が生まれつき無意味になる3つの道」に当てて点検する |
| `/moat-audit` | 出来上がった結果・報告・下書きを読み、信用できない箇所を挙げる。裸の数値、閾値なしの判定語、見出しに出ている未読の条件、混ぜられた母集団、後から動いた閾値、欠けている自明解、外部に固定されていない器具 |
| `/moat-retract` | 撤回を全ての保管先に1巡で伝播させる。その数値が**実際には何の量だったか**と、それに乗っていた判断まで含めて |

両言語あるのはこの README だけです。

## これは何ではないか

- **方法論の講義ではない。**各規則は操作的で、
  **書くべきファイル**か**足すべき条件**を名指しします
- **統計ライブラリではない。**数値は計算しません。
  **数値が意味を持つために何が先に存在していなければならないか**を決めます
- **万能ではない。**上の規則のどれもが、ある1つのプロジェクトで実際に
  起きた事故に由来します。あなたのところで起きる事故の型は違うかもしれません

## 名前の由来

元は日本語の「外堀を埋める」から来ています。本体の作業の前に周辺を固めていく、
という意味で使われていた言葉です。ただし「堀を埋める」は本来、
攻め手が相手の防御を潰す動作なので、スローガンは**「堀を掘る」**にしました。
守るのは自分の結論です。

## 出どころ

ある長期の画像研究プロジェクトが、自分の失敗の台帳を付け続けていました。
その記録で印象的なのは**書かれていないこと**です。
コードを書きすぎて失ったものはほとんど無く、失われたもののほとんどは、
**量を連れずに動いた数値**、**落ちようのない対照**、
**自分自身を測っていた器具**でした。

`plugins/moat/skills/moat/references/incidents.md` に、その事故の記録を
抽象化して置いてあります（プロジェクト固有の内容は除去済み）。
規則が細かすぎると感じたときに読んでください。
